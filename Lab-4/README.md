# Lab-4:SM3 软件实现与优化

基于 **SIMD 寄存器与通用寄存器混合** 的 SM3(GB/T 32905-2016)杂凑算法优化实现,
覆盖 **x86 (AVX2)** 与 **ARM64 (NEON)** 两种架构。

## 目录

| 文件              | 说明                                    |
| ----------------- | --------------------------------------- |
| `sm3.h` / `sm3.c` | 基础实现(纯通用寄存器),作为正确性基准   |
| `sm3_avx2.c`      | x86 AVX2 优化实现(SIMD 扩展 + GPR 压缩) |
| `sm3_neon.c`      | ARM64 NEON 优化实现(同一混合策略)       |
| `sm3_test.c`      | 正确性测试(标准测试向量)+ 性能基准      |
| `Makefile`        | 一键编译 / 测试 / 基准                  |

## 快速开始

```bash
make            # 编译(自动检测 AVX2)
make test       # 运行正确性测试(与国标测试向量比对)
make bench      # 运行性能基准(基础版 vs AVX2 版)
```

## 优化思路:SIMD + GPR 混合

SM3 一个分组的处理分两个阶段,两阶段的**并行性特征截然不同**:

```
64 字节分组 ──消息扩展──> W[0..67] ──64 轮压缩──> 更新 A..H
            (部分可并行)            (强串行依赖)
```

### 1. 消息扩展 —— 用 SIMD 加速

扩展公式:
$$W_j = P_1(W_{j-16} \oplus W_{j-9} \oplus (W_{j-3}\!\!\lll\!15)) \oplus (W_{j-13}\!\!\lll\!7) \oplus W_{j-6}$$

其中 $W_{j-16}\oplus W_{j-9}$、$(W_{j-13}\lll7)\oplus W_{j-6}$ 这些**大项彼此独立**,
可用 SIMD 一次并行计算 4 路(x86 用 256 位 YMM,ARM 用 128 位 NEON 寄存器);
而含依赖链的 $P_1$ 递推($W_{j-3}$ 依赖前面结果)由 **GPR 串行**完成。

### 2. 压缩函数 —— 保留 GPR 串行

64 轮压缩中,每轮的 $SS_1, TT_1, TT_2$ 立即成为下一轮的输入,
是典型的**强数据依赖链**,无法有效向量化;强行 SIMD 化反而会引入
SIMD↔GPR 之间频繁的搬移开销。因此压缩阶段保持通用寄存器串行推进。

> 这种"**扩展用 SIMD、压缩用 GPR**"的混合,是 SM3 在通用 CPU 上最现实的优化路径。

## 实现要点

- **x86 AVX2**:`_mm256_xor_si256` / `_mm256_slli_epi32` / `_mm256_srli_epi32`
  组合实现 4 路并行循环左移与异或;
- **ARM64 NEON**:`veorq_u32` / `vshlq_n_u32` / `vshrq_n_u32` / `vorrq_u32`
  实现同样的 4 路并行;
- 两个优化版本对外接口与基础版一致,便于对比测试。

## 正确性验证

## 性能参考

在 x86-64(支持 AVX2)上,64 KB 数据重复 2000 次:

| 实现      | 吞吐      |
| --------- | --------- |
| 基础实现  | ~227 MB/s |
| AVX2 优化 | ~267 MB/s |

消息扩展阶段经 SIMD 化后带来约 **17%** 的整体提升。SM3 的压缩部分是
主要耗时且难以向量化,因此提升幅度受限于扩展阶段占比。

## 跨架构说明

- 在 **x86** 机器上编译时,`sm3_neon.c` 自动编译为退化为参考实现的占位版本,
  保证整个工程可链接、可运行;
- 在 **ARM64**(如树莓派、Apple Silicon、鲲鹏/飞腾)上编译时,NEON 版本
  自动启用,`-mavx2` 不会被使用。两种架构共用同一份源码与测试。
